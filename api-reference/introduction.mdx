The Sketa REST API reads and writes the scenes, scene content, collections, members, invites, teams and audit log of one workspace. It is part of **Sketa Plus**.

## Base URL

```
https://sketa.app/api/v1
```

## Authentication

Create an API key in **Settings → API keys** (see [API keys](/knowledge-base/developers/api-keys)) and send it as a Bearer token:

```bash
curl https://sketa.app/api/v1/workspace \
  -H "Authorization: Bearer sketa_YOUR_API_KEY" \
  -H "Accept: application/json"
```

Every key is bound to one workspace, the one it was created in. There are two kinds:

- **Personal keys** act as the member who created them, with the same permissions as in the app, including their private collection. They stop working if the member leaves the workspace or an admin turns personal keys off.
- **Workspace keys** act as the workspace. They can do what an admin can over shared resources (members, invites, teams, audit log, shared collections and their scenes), but never see private collections or collections restricted to teams. Scenes they create have `createdBy: null`.

Only API keys work here; a signed-in browser session does not.

## Abilities

Each key carries abilities, and every endpoint needs one (shown on each endpoint page):

| Ability | Endpoints |
| --- | --- |
| `workspace:read`, `workspace:write` | `/workspace` |
| `users:read`, `users:write` | `/users`, `/blocks` |
| `invites:read`, `invites:write` | `/invites` |
| `collections:read`, `collections:write` | `/collections` |
| `scenes:read`, `scenes:write` | `/scenes`, `/scenes/{scene}/content` |
| `audit-logs:read` | `/audit-logs` |
| `teams:read`, `teams:write` | `/teams` |

`GET /collections/{collection}/scenes` needs both `collections:read` and `scenes:read`. A key without the ability gets `403 This API key is missing the <ability> ability.` Abilities never widen what the key's user may do: a member's personal key cannot change roles even with `users:write`.

## Responses

- Single resources are wrapped in `data`: `{"data": {"id": "...", "name": "..."}}`.
- Field names are camelCase; ids are UUIDs; timestamps are ISO 8601.
- Creating returns `201`; deleting returns `204` with no body.
- Scene content (`/scenes/{scene}/content`) is not wrapped: reads return `{contentVersion, elements, files}` and writes return `{contentVersion}`. See [Scene content](/api-reference/scene-content).
- Deleting a scene or a collection moves it to the trash, restorable from the app for 30 days.

## Pagination

Lists are paginated with a fixed page size (25 today). Pass `?page=2` to move on, and read the size from `meta.per_page` instead of assuming it:

```json
{
  "data": [ ... ],
  "links": { "first": "...?page=1", "last": "...?page=3", "prev": null, "next": "...?page=2" },
  "meta": { "current_page": 1, "from": 1, "last_page": 3, "path": "...", "per_page": 25, "to": 25, "total": 61 }
}
```

## Errors

Every error has the same shape:

```json
{
  "statusCode": 404,
  "error": "Not Found",
  "message": "Not found."
}
```

Validation errors (`422`) add the messages per field:

```json
{
  "statusCode": 422,
  "error": "Unprocessable Content",
  "message": "The name field is required.",
  "errors": { "name": ["The name field is required."] }
}
```

| Status | When |
| --- | --- |
| `401` | No key, an invalid or revoked key, `API key expired.`, or `API key revoked.` (a personal key whose member left the workspace) |
| `402` | `Sketa Plus required.` The key's workspace does not have Plus. |
| `403` | The key lacks the ability; the acting user may not do this; `Personal API keys are turned off in this workspace.`; or `Workspace is read-only.` on a write |
| `404` | `Not found.` The resource does not exist, is in another workspace, or is not visible to the key (another member's private collection, a restricted collection for a workspace key) |
| `413` | The body is over 10 MB (scene content and scene creation) |
| `422` | Invalid input |
| `429` | Too many requests |

## Read-only workspaces

When a workspace's Plus ends it becomes read-only: `GET` requests keep working, and every write returns `403 Workspace is read-only.`

## Rate limits

- **120 requests per minute per key**, and
- **600 requests per minute per workspace**, across all its keys.

Over either limit you get `429` with a `Retry-After` header: wait that many seconds before retrying.

## Audit log

Every write made through the API is recorded in the workspace's [audit log](/knowledge-base/workspace/audit-log) with the source **API** and the key that made it.

## AI assistants

The [MCP server](/ai/introduction) at `https://sketa.app/mcp` accepts the same keys and enforces the same permissions, so an assistant can do whatever the key could do over REST.
