An API key gives a script, an integration or an AI assistant access to **one workspace** through the [REST API](/api-reference/introduction) and the [MCP server](/ai/introduction). Find them in **Settings → API keys**.

<Note>
  API keys need Sketa Plus. If the workspace loses Plus, its keys are refused with `402 Sketa Plus required.`
</Note>

## Personal and workspace keys

| | **Personal** | **Workspace** |
| --- | --- | --- |
| Acts as | You, with your permissions | The workspace |
| Sees | What you see, including your private collection | Shared collections only, never private or team-restricted ones |
| Who can create | Any member, if **Allow personal keys** is on | Admins |
| Stops working when | You leave the workspace, or personal keys are turned off | It is deleted, regenerated or expires |

Workspace keys can do what an admin can over shared resources: manage members, invites and teams, and read the audit log.

## Create a key

<Steps>
  <Step title="Create key">
    In **Settings → API keys**, click **Create key**.
  </Step>
  <Step title="Name, scope, abilities and expiry">
    - **Name**, for example "Zapier".
    - **Acts as**: **Personal** or **Workspace** (admins).
    - **Abilities**: what the key may do. Leave them all for **All abilities**.
    - **Expires**: **Never**, or in 30, 90 or 365 days.
  </Step>
  <Step title="Copy your API key">
    The key is shown once, right after you create it. It starts with `sketa_`. Store it somewhere safe.
  </Step>
</Steps>

## Abilities

| Ability | Lets the key |
| --- | --- |
| `workspace:read` / `workspace:write` | Read / update the workspace |
| `users:read` / `users:write` | Read / manage members and blocked e-mails |
| `invites:read` / `invites:write` | Read / manage invites |
| `collections:read` / `collections:write` | Read / manage collections |
| `scenes:read` / `scenes:write` | Read / manage scenes and their content |
| `audit-logs:read` | Read audit logs |
| `teams:read` / `teams:write` | Read / manage teams |

Abilities limit the key on top of the permissions of whoever it acts as: a personal key of a member with `users:write` still cannot remove members.

## Use a key

```bash
curl https://sketa.app/api/v1/workspace \
  -H "Authorization: Bearer sketa_YOUR_API_KEY"
```

The same header connects an MCP client to `https://sketa.app/mcp`. See [Authentication](/ai/introduction#authentication).

Treat a key like a password: never commit it or put it in client-side code.

## The key list

You see your own personal keys; admins also see the workspace keys. Each shows its abilities, who created it, when it was last used and when it expires (**Never expires**, **Expires** or **Expired**).

- **Regenerate** replaces the key's token: the current one stops working at once. Type `REGENERATE` to confirm.
- **Delete** removes the key: apps using it stop working at once. Type `DELETE` to confirm.
