An API key gives a script, an integration or an AI assistant access to **one workspace** through the [REST API](/api-reference/introduction) and the [MCP server](/ai/introduction). Find them in **Settings → Workspace → API keys** (`/settings/workspace/api-keys`), for the workspace you are in; switch workspaces to manage another one's keys.

<Note>
  API keys need Sketa Plus. On a Free workspace the page shows **API keys are part of Plus** with an **Upgrade to Plus** button for admins (members are asked to contact an admin). If the workspace loses Plus, its keys are refused with `402 Sketa Plus required.`
</Note>

## How keys work

Every key belongs to the workspace it was created in **and** to the member who created it, and acts as that member:

- It has your permissions, exactly as in the app: it sees your private collection and the team-restricted collections you can open, and an admin's key can do what an admin can (manage members, invites and teams, read the audit log).
- Any member of a Plus workspace can create their own keys.
- It stops working when you leave the workspace or are removed from it, or when it is deleted, regenerated or expires.

## Create a key

<Steps>
  <Step title="Create key">
    In **Settings → Workspace → API keys**, click **Create key** (on an empty page, the button sits under **No API keys yet**).
  </Step>
  <Step title="Name, abilities and expiry">
    - **Name**, for example "Zapier".
    - **Abilities**: what the key may do. Leave them all for **All abilities**.
    - **Expires**: **Never**, or in 30, 90 or 365 days.
  </Step>
  <Step title="Copy your API key">
    The key is shown once, right after you create it. It starts with `sketa_`. Store it somewhere safe.
  </Step>
</Steps>

## Abilities

| Ability | Lets the key |
| --- | --- |
| `workspace:read` / `workspace:write` | Read / update the workspace |
| `users:read` / `users:write` | Read / manage members and blocked e-mails |
| `invites:read` / `invites:write` | Read / manage invites |
| `collections:read` / `collections:write` | Read / manage collections |
| `boards:read` / `boards:write` | Read / manage boards and their content |
| `audit-logs:read` | Read audit logs |
| `teams:read` / `teams:write` | Read / manage teams |
| `libraries:read` | Read the public library catalog |

Abilities limit the key on top of the permissions of whoever it acts as: the key of a member with `users:write` still cannot remove members.

## Use a key

```bash
curl https://sketa.app/api/workspace \
  -H "Authorization: Bearer sketa_YOUR_API_KEY"
```

The same header connects an MCP client to `https://sketa.app/mcp`. See [Authentication](/ai/introduction#authentication).

Treat a key like a password: never commit it or put it in client-side code.

## The key list

Members see only their own keys. Admins see the keys of every member of the workspace, with the name and photo of who created each one. Each key shows its abilities, when it was last used and when it expires (**Never expires**, **Expires** or **Expired**).

You can regenerate or delete your own keys; admins can regenerate or delete anyone's (a regenerated key still acts as the member who created it).

- **Regenerate** replaces the key's token: the current one stops working at once. Type `REGENERATE` to confirm.
- **Delete** removes the key: apps using it stop working at once. Type `DELETE` to confirm.
