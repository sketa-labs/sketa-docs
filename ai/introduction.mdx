Sketa has a built-in [MCP (Model Context Protocol)](https://modelcontextprotocol.io) server that lets AI assistants work in your workspace directly. Your assistant can draw diagrams with automatic layout, add shapes, arrows, sticky notes and images, build slide decks, take screenshots to check its work, and manage scenes, collections, members, invites and teams, all through natural language.

## What is MCP?

MCP is an open protocol that connects AI assistants to external tools and data. Instead of you copying JSON around, the assistant calls Sketa's tools itself.

## Available tools

The server exposes 46 tools. See the [Tools reference](/ai/tools-reference) for every input, and the [Format guides](/ai/format-guides) for how the assistant is told to lay out diagrams, slides and freeform boards.

| Category | What your assistant can do |
|----------|----------------------------|
| **Drawing** | Search a scene, read its content, add, change and delete elements from simple skeletons, draw diagrams with automatic layout, add images from a URL or base64, take a PNG screenshot of the scene or one frame |
| **Slides** | Add slides (frames) with a safe area and layout regions, list them, change titles, presenter notes, order and visibility |
| **Scenes and collections** | List, search, create, rename, move, pin and delete scenes; list, create, edit and delete collections |
| **Workspace and people** | Read and rename the workspace; list members, change roles, remove and block, unblock; list, send, change and cancel invites; manage teams and their members |
| **Audit log** | Read the workspace's audit log with filters |

### What MCP cannot do

- Restore from the trash or from version history, manage public links, guests, comments, billing or API keys. Use the [web app](https://sketa.app/dashboard) for these.
- Use Sketa's own AI features (text to diagram, wireframe to code). The assistant is the AI: it draws through the tools instead.

## How it works

<Note>
  MCP is part of **Sketa Plus**: the connection must be bound to a Plus workspace. See [Plans and billing](/knowledge-base/workspace/plans-and-billing).
</Note>

<Steps>
  <Step title="Add the Sketa MCP server in your assistant">
    Use your assistant's MCP configuration to add a remote HTTP server pointing to `https://sketa.app/mcp`. Each [client guide](#next-steps) below has the exact command or settings file.
  </Step>
  <Step title="Sign in and pick a workspace">
    The first time the assistant connects, Sketa opens **Connect an app** in your browser. Sign in, choose the **Workspace** this connection may use ("The app only reaches the workspace you pick.") and click **Allow**. The assistant keeps the OAuth token from then on, with automatic refresh.
  </Step>
  <Step title="Start using natural language">
    Ask your assistant to work in Sketa. For example: "Draw the architecture of our checkout service in a new scene" or "Turn these notes into a five-slide deck."
  </Step>
</Steps>

## Manage connections in Sketa

Open **Settings → Workspace → MCP** (`/settings/workspace/mcp`) for the workspace you are in:

- **Connected apps** lists the assistants you signed in with for this workspace, with when each was last used. Members see only their own; admins see every member's connections, with the name and photo of who connected each one, and can disconnect any of them. Use **Disconnect** to sign one out: it has to connect again before it can use Sketa. The list updates by itself as soon as a new connection is approved.
- **Connect an app** has the server URL, the command or config to paste and the steps for Claude, ChatGPT, Claude Code, Cursor, VS Code, Codex, Gemini CLI and any other MCP app, each with a link to its guide below.

On a Free workspace the page shows **MCP is part of Plus** instead, with **Upgrade to Plus** for admins.

## Server URL

```
https://sketa.app/mcp
```

## Authentication

The server accepts two kinds of credentials. Both are bound to one Plus workspace.

### OAuth (recommended)

Sketa's MCP server supports **OAuth 2.1** with Dynamic Client Registration, PKCE and the `mcp:use` scope. Modern MCP clients detect it from the `.well-known` discovery endpoints: you only give them the URL and the browser sign-in does the rest.

An OAuth connection acts as **you**, with every ability, in the workspace you picked on the consent screen: it sees your private collection and can do what you can do in the app. To work in another workspace, connect again and pick it. Only Plus workspaces can be picked; if you have none, the consent screen tells you to upgrade one or join one first.

### API key

For clients that cannot complete OAuth, and for scripts, send an [API key](/knowledge-base/developers/api-keys) as a header:

```
Authorization: Bearer sketa_YOUR_API_KEY
```

The key acts as the member who created it and its abilities apply exactly as on the REST API: tools outside the key's abilities answer "This connection is missing the *ability* ability."

## Permissions

The MCP server resolves the same actor as the [REST API](/api-reference/introduction), so permissions are identical:

- **Members** can create, edit, move and delete scenes and collections they can see, and read members and invites.
- **Admins** can also rename the workspace, change roles, remove and block members, send and cancel invites, manage teams and read the audit log.
- Anything outside the workspace, or not visible to the connection (another member's private collection; a team-restricted collection you cannot open), answers "Not found."
- In a **read-only** workspace (Plus ended), every tool that changes something answers "Workspace is read-only."

Every change made through MCP is recorded in the [audit log](/knowledge-base/workspace/audit-log) with the source **MCP**. Tool calls are limited to 120 per minute per connection.

## Troubleshooting

<AccordionGroup>
  <Accordion title="HTTP 402 — Sketa Plus required">
    The workspace the connection (or API key) is bound to does not have Sketa Plus. Subscribe in **Settings → Workspace → Billing**, or reconnect and pick a Plus workspace.
  </Accordion>
  <Accordion title="HTTP 401 — Unauthenticated">
    The OAuth session expired and refresh failed, or the token or API key is missing, malformed, revoked or expired (`API key expired.`). `API key revoked.` means you are no longer a member of the workspace the connection was bound to. Re-run the assistant's connect flow, or create a new key.
  </Accordion>
  <Accordion title="A tool says “This connection is missing the … ability”">
    The API key does not carry that ability. Create a key with the abilities you need, or connect with OAuth (which carries every ability).
  </Accordion>
  <Accordion title="A tool says “Not found.”">
    The id is from another workspace, or the connection cannot see it: another member's private collection, or a team-restricted collection you cannot open. Ask the assistant to list the resources first instead of guessing ids.
  </Accordion>
  <Accordion title="Browser doesn't open during sign-in">
    Some clients print the authorize URL to the terminal instead of opening the browser when running over SSH or inside a container. Copy the URL into a local browser and finish the flow. If the callback cannot reach the client, connect with an API key header instead.
  </Accordion>
</AccordionGroup>
