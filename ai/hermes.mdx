[Hermes Agent](https://hermes-agent.nousresearch.com/) is the open-source agent from [Nous Research](https://nousresearch.com/). Add Sketa as a remote HTTP MCP server and Hermes can draw diagrams and slides in your Sketa workspace from the Hermes CLI, [Desktop](https://hermes-agent.nousresearch.com/docs/user-guide/desktop) app, or any [messaging gateway](https://hermes-agent.nousresearch.com/docs/user-guide/messaging) already running on that install.

This page is for **Hermes as an MCP client** — you point Hermes at Sketa. It is not [`hermes mcp serve`](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp), which exposes Hermes itself to other agents.

<Note>
  Sketa is not in the [Nous-approved MCP catalog](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp). `hermes mcp` with no arguments (or `hermes mcp picker` / `hermes mcp install`) only lists catalog entries. Do not look for a Sketa tile. Add a custom HTTP server with `auth: oauth`.
</Note>

## Prerequisites

- [Hermes Agent](https://hermes-agent.nousresearch.com/docs/getting-started/installation) installed (CLI and/or [Desktop](https://hermes-agent.nousresearch.com/docs/user-guide/desktop)). The [standard install](https://hermes-agent.nousresearch.com/docs/guides/use-mcp-with-hermes) already includes MCP. If a command says MCP extras are missing:

  ```bash
  cd ~/.hermes/hermes-agent
  uv pip install -e ".[mcp]"
  ```

- A Sketa account in a Plus workspace ([plans and billing](/knowledge-base/workspace/plans-and-billing))

## Server URL

Use this exact URL. Do not add a trailing slash. Do not paste an OAuth authorize URL. Do not use `/api`.

```
https://sketa.app/mcp
```

Leave the transport at Hermes' default (Streamable HTTP). Do not set `transport: sse`.

## Setup

Hermes stores servers in `~/.hermes/config.yaml` under `mcp_servers`. For a hosted OAuth server it uses `url` + `auth: oauth`, then completes the browser flow on [first connect or `hermes mcp login`](https://hermes-agent.nousresearch.com/docs/guides/oauth-over-ssh).

Pick **one** way to add the server. Do not run `login` after a successful `add` — `hermes mcp login` [force-reauthenticates](https://hermes-agent.nousresearch.com/docs/reference/cli-commands): it deletes the token on disk and starts the browser flow again.

<Steps>
  <Step title="Add the Sketa MCP server">
    **CLI add.** [`hermes mcp add`](https://hermes-agent.nousresearch.com/docs/reference/cli-commands) writes the server and immediately connects (that connect is the first OAuth). Give the probe time to finish the browser sign-in:

    ```bash
    hermes mcp add sketa --url https://sketa.app/mcp --auth oauth --connect-timeout 300
    ```

    `--auth` only accepts `oauth` or `header`. Use **`oauth`**.

    1. Sign in to Sketa, pick the **Workspace** this connection may use and click **Allow** (to use another workspace, connect again and pick it)
    2. When it asks `Enable all N tools? [Y/n/select]`, answer **Y**. **n** cancels and does **not** save the server. **select** writes a `tools.include` list and hides everything else (including the drawing and delete tools)

    If connect fails, Hermes may ask **Save config anyway?** and store the entry with `enabled: false`. Set `enabled: true` in `config.yaml`, then run login below.

    **YAML, then login.** Same config [Hermes documents for OAuth HTTP servers](https://hermes-agent.nousresearch.com/docs/reference/mcp-config-reference). Write the block in [Manual configuration](#manual-configuration). If Hermes is already running, do **not** wait for in-session auto-reload — [that reload only waits 30 seconds](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp), which is too short for OAuth. From a **fresh** terminal:

    ```bash
    hermes mcp login sketa
    ```

    `login` waits up to five minutes. Use this same command later to re-authenticate.

    **Desktop.** Open the [Add to Hermes](#hermes-desktop) link, confirm the dialog, then `login` if the app has not already completed OAuth.
  </Step>
  <Step title="Finish the browser sign-in">
    On first connect, Hermes [prints an authorize URL, opens your browser when it can, and waits on a loopback callback](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp). You do not paste an API key, Client ID, or Client Secret — Sketa uses Dynamic Client Registration.

    A successful run writes `~/.hermes/mcp-tokens/sketa.json` (mode `0o600`). Later sessions reuse it and refresh the token. Re-authorization only happens when refresh fails — or when you run `login`.

    If the browser cannot reach `http://127.0.0.1:<port>/callback` (SSH, VPS, headless gateway), see [Remote and headless Hermes](#remote-and-headless-hermes).
  </Step>
  <Step title="Reload and verify">
    ```bash
    hermes mcp list
    hermes mcp test sketa
    hermes chat
    ```

    `hermes mcp list` should include `sketa`. `hermes mcp test sketa` should connect and list tools.

    If a session is already open, run `/reload-mcp`. Then ask the prompt [Hermes documents](https://hermes-agent.nousresearch.com/docs/guides/use-mcp-with-hermes) for this check:

    ```
    Tell me which MCP-backed tools are available right now.
    ```

    You should see Sketa tools. Then:

    ```
    List my Sketa scenes
    ```

    Hermes registers each tool as `mcp__<server>__<tool>` ([config reference](https://hermes-agent.nousresearch.com/docs/reference/mcp-config-reference)). Hyphens become underscores, so `list-scenes-tool` is `mcp__sketa__list_scenes_tool`. You do not type that name — ask in plain language. If Hermes answers without tools, tell it to use the **sketa** MCP server.

    See the [Tools reference](/ai/tools-reference) for every tool and the recommended drawing workflow.
  </Step>
</Steps>

## Authentication

Use **OAuth**: a browser sign-in that binds the connection to one Plus workspace you pick. Leave OAuth client ID and secret empty: Sketa supports Dynamic Client Registration.

Sketa's MCP server also accepts an [API key](/knowledge-base/developers/api-keys) sent as an `Authorization: Bearer sketa_...` header, if you prefer a key to a browser sign-in. A key carries only its abilities, and a workspace key sees shared collections only.

To disconnect, remove the server from Hermes. Leaving the workspace also ends the connection.

## What you can do

Once the server is authorized, Hermes can:

| Task | Examples |
|------|----------|
| **Drawing** | Draw diagrams with automatic layout; add shapes, arrows, sticky notes and images; search and edit scenes; take screenshots to check the result |
| **Slides** | Add slides, write speaker notes, reorder and hide slides |
| **Scenes and collections** | List, search, create, rename, move, pin and delete |
| **Workspace** | Read the workspace; manage members, invites and teams; read the audit log |

Members, invites, teams and the audit log need an admin. See [Permissions](/ai/introduction#permissions).

The same tools are then available in `hermes chat`, Hermes Desktop, and any [messaging gateway](https://hermes-agent.nousresearch.com/docs/user-guide/messaging) on that install (Telegram, Discord, Slack, and the rest).

## Manual configuration

Equivalent config written by `hermes mcp add` — the [OAuth HTTP shape](https://hermes-agent.nousresearch.com/docs/reference/mcp-config-reference):

```yaml
mcp_servers:
  sketa:
    url: "https://sketa.app/mcp"
    auth: oauth
```

Save in `~/.hermes/config.yaml`, then run `hermes mcp login sketa` from a fresh terminal. Do not add `headers`, `transport`, or `oauth.client_id`.

To hide the server without deleting the block, set `enabled: false`. To remove it:

```bash
hermes mcp remove sketa
```

To change which tools Hermes sees after a successful login:

```bash
hermes mcp configure sketa
```

## Hermes Desktop

Desktop shares `~/.hermes/config.yaml`. Desktop settings include an **MCP servers** pane. After you add and authorize the server, open that pane or start a new Desktop chat so the tools load.

One-click install ([Add to Hermes](https://hermes-agent.nousresearch.com/docs/reference/mcp-config-reference)):

```
hermes://mcp/install?name=sketa&config=eyJ1cmwiOiJodHRwczovL2FwcC50cnlwb3N0Lml0L21jcC90cnlwb3N0IiwiYXV0aCI6Im9hdXRoIn0
```

Opening that link does **not** install by itself. Desktop shows the name and the full config; you confirm. Existing names are never overwritten — you rename or cancel. Then run `hermes mcp login sketa` if the app has not already completed OAuth.

## Remote and headless Hermes

When Hermes is not on the same machine as your browser, the OAuth callback to `http://127.0.0.1:<port>/callback` never hits the listener. This is the Sketa MCP login, not Hermes' model-provider sign-in.

Escalation from [OAuth over SSH](https://hermes-agent.nousresearch.com/docs/guides/oauth-over-ssh) and the [mcp-oauth-remote-gateway](https://hermes-agent.nousresearch.com/docs/user-guide/skills/optional/mcp/mcp-mcp-oauth-remote-gateway) skill: dashboard in your browser first, then paste-back or an SSH tunnel, then the headless skill.

<Accordion title="Hermes dashboard (try this first on a remote gateway)">
  A remote Hermes often also runs the [web dashboard](https://hermes-agent.nousresearch.com/docs/user-guide/features/web-dashboard). Adding or re-authing an OAuth MCP server from the dashboard in **your** browser avoids the loopback-callback problem. Look for the MCP / Connectors section (same `mcp_servers` block as the CLI). If `HERMES_DASHBOARD_PUBLIC_URL` is set on the host, that is the public URL to open.
</Accordion>

<Accordion title="Paste the redirect URL back">
  On an interactive terminal, `hermes mcp login sketa` prints the authorize URL and asks you to paste the redirect. Open the URL on your laptop, pick the workspace and click **Allow**, then copy the full URL from the address bar (the page may show a connection error — that is expected) and paste it at the Hermes prompt. A bare `?code=…&state=…` string works too. Official walkthrough: [OAuth over SSH / Remote Hosts](https://hermes-agent.nousresearch.com/docs/guides/oauth-over-ssh).
</Accordion>

<Accordion title="SSH port forward">
  Hermes prints the port it bound (`Waiting for callback on http://127.0.0.1:<port>/callback`). In a separate laptop terminal:

  ```bash
  ssh -N -L <port>:127.0.0.1:<port> user@remote-host
  ```

  Then finish the authorize URL in your local browser so the redirect tunnels to the remote listener. Hermes may auto-bump the port if the preferred one is busy — copy it from the latest `Waiting for callback` line.
</Accordion>

<Accordion title="Public HTTPS callback (Tailscale Funnel / reverse proxy)">
  Hermes also supports a proxied callback when a public HTTPS URL forwards to the listener. Pin the port and set `oauth.redirect_uri` ([MCP guide](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp)):

  ```yaml
  mcp_servers:
    sketa:
      url: "https://sketa.app/mcp"
      auth: oauth
      oauth:
        redirect_port: 8765
        redirect_uri: "https://oauth.example.ts.net/callback"
  ```

  Then run `hermes mcp login sketa`. You do not need this on a laptop where the browser and Hermes share a machine.
</Accordion>

<Accordion title="No interactive terminal (gateway / bot only)">
  If you cannot open the dashboard and cannot paste at a prompt, install Nous' skill and let it walk the flow:

  ```bash
  hermes skills install official/mcp/mcp-oauth-remote-gateway
  ```

  It writes tokens under `~/.hermes/mcp-tokens/`, then you run `/reload-mcp`. Docs: [mcp-oauth-remote-gateway](https://hermes-agent.nousresearch.com/docs/user-guide/skills/optional/mcp/mcp-mcp-oauth-remote-gateway).
</Accordion>

<Accordion title="Tokens landed in the wrong ~/.hermes">
  [OAuth over SSH](https://hermes-agent.nousresearch.com/docs/guides/oauth-over-ssh): tokens are written under the Linux user that ran the login. If the gateway or systemd unit runs as `root` or a dedicated `hermes` user, authenticate as **that** user (`sudo -u hermes -i` or equivalent) so `~/.hermes/mcp-tokens/sketa.json` is the file the running agent reads.
</Accordion>

## Useful commands

| Command | What it does |
|---------|----------------|
| `hermes mcp add sketa --url https://sketa.app/mcp --auth oauth --connect-timeout 300` | Write the server and run OAuth during the connect probe |
| `hermes mcp login sketa` | Wipe the cached token and run OAuth again (or first time after a YAML-only add) |
| `hermes mcp reauth sketa` | Same as `login` for one server (`--all` walks every OAuth server) |
| `hermes mcp list` | Show configured servers |
| `hermes mcp test sketa` | Probe connectivity and tools |
| `hermes mcp configure sketa` | Change the tool checklist |
| `hermes mcp remove sketa` | Delete the server entry and clean up its OAuth tokens |
| `/reload-mcp` | Reload MCP inside a live `hermes chat` session |

## Troubleshooting

<AccordionGroup>
  <Accordion title="hermes mcp add or login times out before I finish OAuth">
    `add` without `--connect-timeout` uses a short connect probe — too short for a browser sign-in. Retry add with `--connect-timeout 300`, or write the YAML and run `hermes mcp login sketa` in a **new** terminal (`login` waits five minutes). If you edited `config.yaml` inside a running session, [do not wait for auto-reload](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp) — that path only waits 30 seconds. Do not run `login` right after a successful add — that wipes the token you just got.
  </Accordion>
  <Accordion title="The server is in config but Hermes does not call Sketa tools">
    Confirm `~/.hermes/mcp-tokens/sketa.json` exists, and that `enabled` is not `false` (a failed `mcp add` can save the server disabled). Run `hermes mcp test sketa`, then `/reload-mcp` or a new `hermes chat`. Ask which MCP tools are available. If `tools.include` was saved as a short list, run `hermes mcp configure sketa` and enable everything (or delete the `tools` block). If `/reload-mcp` is silent and no tools appear, the reload can fail quietly — run `hermes mcp test sketa` and start a new session.
  </Accordion>
  <Accordion title="login lists tools but every real call times out">
    Hermes documents this when DCR failed and no token landed on disk. For Sketa, DCR should work. Check that `auth: oauth` is set, no `headers.Authorization` is present, and `~/.hermes/mcp-tokens/sketa.json` exists after login. If it is missing, run `hermes mcp login sketa` again — do not add a Client ID.
  </Accordion>
  <Accordion title="Hermes cannot reach the server">
    `https://sketa.app/mcp` is public. Check that the **Hermes host** can reach the internet over HTTPS.
  </Accordion>
  <Accordion title="HTTP 402 — Sketa Plus required">
    The connection works, but the workspace it is bound to does not have Sketa Plus. Subscribe in **Settings → Billing**, or reconnect and pick a Plus workspace. See [Introduction](/ai/introduction#troubleshooting).
  </Accordion>
  <Accordion title="HTTP 401 or I need to sign in again">
    The token expired or was revoked. Run `hermes mcp login sketa` again.
  </Accordion>
  <Accordion title="A tool says “Not found.”">
    The resource is outside the workspace the connection is bound to, or you cannot see it (another member's private collection; a team-restricted collection for a workspace key). Ask the assistant to list scenes or collections first instead of guessing ids.
  </Accordion>
  <Accordion title="I used hermes mcp install sketa and nothing happened">
    `install` only accepts [catalog](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp) names. Sketa is not in that catalog. Use `hermes mcp add` with `--url` and `--auth oauth`.
  </Accordion>
</AccordionGroup>
