[GitHub Copilot](https://github.com/features/copilot) supports MCP servers in agent mode, allowing you to connect Sketa directly to your VS Code workflow.

## Prerequisites

- VS Code with the GitHub Copilot extension installed
- Copilot agent mode enabled
- A Sketa account in a Plus workspace ([plans and billing](/knowledge-base/workspace/plans-and-billing))

## Setup (IDE agent mode)

<Steps>
  <Step title="Create the MCP configuration file">
    In your project root, create or edit `.vscode/mcp.json`:

    ```json
    {
      "servers": {
        "sketa": {
          "type": "http",
          "url": "https://sketa.app/mcp"
        }
      }
    }
    ```

    No `Authorization` header — Copilot uses VS Code's MCP layer, which discovers OAuth from the URL.
  </Step>
  <Step title="Reload VS Code">
    Reload the window to load the new MCP configuration.
  </Step>
  <Step title="Sign in through your browser">
    Open Copilot Chat in agent mode. VS Code prompts you to sign in to Sketa. In the browser, pick the **Workspace** this connection may use and click **Allow**; the server flips to **Connected**. To use another workspace, connect again and pick it.
  </Step>
  <Step title="Verify the connection">
    Ask Copilot:

    ```
    List my Sketa scenes
    ```
  </Step>
</Steps>

<Tip>
  VS Code uses `"servers"` as the top-level key (not `"mcpServers"`). This is different from most other MCP clients.
</Tip>

## Copilot coding agent (cloud)

GitHub's **coding agent** (the one that runs on GitHub's infrastructure to handle issues and PRs) does not support OAuth for remote MCP servers. Sketa's MCP endpoint also accepts an API key, so you can connect the coding agent with an `Authorization: Bearer sketa_...` header from a key created in **Settings → API keys** (see [API keys](/knowledge-base/developers/api-keys)), if your coding agent MCP configuration lets you set headers. Store the key as a secret, never in the repository.

Or use Copilot's **IDE agent mode** (above), or call the [REST API](/api-reference/introduction) from Actions and scripts with the same key.

## Global IDE configuration

To make Sketa available across all projects in your IDE, open the command palette and run **MCP: Open User Configuration** to add the server to your user-level settings.
