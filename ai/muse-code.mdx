[Muse Code](https://dev.meta.ai/docs/muse-code) is Meta's terminal coding agent. You can connect it to Sketa's MCP server and draw and organize your scenes in natural language.

The personal agent (the character on [muse.ai](https://muse.ai)) is [Muse AI Agent](/ai/muse).

## Prerequisites

- Muse Code installed:

  ```bash
  curl -fsSL https://dev.meta.ai/install.sh | bash
  ```

- A Sketa account in a Plus workspace ([plans and billing](/knowledge-base/workspace/plans-and-billing))

## Setup

<Steps>
  <Step title="Start Muse Code">
    ```bash
    muse
    ```
  </Step>
  <Step title="Ask it to add the Sketa MCP server">
    Paste the URL and let Muse write the config. For example:

    ```
    Add the Sketa MCP server at https://sketa.app/mcp
    ```

    Muse names the server `sketa` and tells you to authorize it with:

    ```bash
    muse mcp login sketa
    ```
  </Step>
  <Step title="Authorize in the browser">
    Run that command in your terminal (outside the Muse session if it printed it as a next step). Muse opens a browser to Sketa. Sign in, pick the **Workspace** this connection may use and click **Allow**. To use another workspace, connect again and pick it.

    The login argument must match the server key in settings — `sketa` if that's the name Muse chose.
  </Step>
  <Step title="Use Sketa in Muse Code">
    Back in the session, ask:

    ```
    List my Sketa scenes
    ```
  </Step>
</Steps>

<Note>
  Sketa MCP uses **OAuth** with the `mcp:use` scope here (it also accepts an API key sent as an `Authorization: Bearer` header). After `muse mcp login sketa`, Muse stores and refreshes the grant. To disconnect: `muse mcp logout sketa`.
</Note>

<Note>
  MCP tools in Muse Code are **not sandboxed**. They run as a direct network connection, outside the filesystem sandbox. Approval still applies.
</Note>

## Manual configuration

If you prefer to edit the file yourself, put this in `~/.config/muse/settings.json`. The file **must** include `"schema_version": 1`. Muse Code 1.1 writes the block under `mcpServers` (not `mcp_servers`):

```json
{
  "schema_version": 1,
  "mcpServers": {
    "sketa": {
      "mode": "optional",
      "transport": "streamable_http",
      "url": "https://sketa.app/mcp"
    }
  }
}
```

Merge into an existing file. Do not add a second `mcp_servers` block alongside `mcpServers` — that faults the config and `muse mcp login` refuses to run. Then:

```bash
muse mcp login sketa
```

No `Authorization` header. OAuth is discovered from the URL.
