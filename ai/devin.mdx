[Devin](https://docs.devin.ai/get-started/devin-intro) is Cognition's AI software engineer. Add Sketa as a custom MCP server and Devin can draw diagrams and slides in your Sketa workspace from [Devin Cloud](https://app.devin.ai), [Devin CLI](https://cli.devin.ai), or [Devin Desktop](https://docs.devin.ai/desktop/devin-desktop-faq).

This page is for **Devin as an MCP client** — you point Devin at Sketa. It is not the [Devin MCP server](https://docs.devin.ai/work-with-devin/devin-mcp) at `https://mcp.devin.ai/mcp`, which exposes Devin itself to other agents. Do not use `mcp.devin.ai` as the Sketa URL, and do not paste a Devin `cog_` API key into the Sketa config.

<Note>
  Sketa is not in [Devin's MCP marketplace](https://docs.devin.ai/work-with-devin/mcp). Do not look for a Sketa tile. Add a **custom HTTP** server with **OAuth**.
</Note>

## Prerequisites

- A [Devin](https://app.devin.ai) account
- A Sketa account in a Plus workspace ([plans and billing](/knowledge-base/workspace/plans-and-billing))
- On Devin Cloud, the **Manage MCP Servers** permission — required both to add a custom server and to complete OAuth. If you don't have it, ask an organization admin or use **Suggest MCP Integration**.

## Server URL

Use this exact URL. Do not add a trailing slash. Do not paste `/api`, an OAuth authorize URL, or `https://mcp.devin.ai/mcp`.

```
https://sketa.app/mcp
```

Transport is **HTTP** (Streamable HTTP). Do not pick **SSE** or **STDIO**.

## Which Devin surface

Devin has three MCP configs. They do **not** share OAuth tokens. Configure the surface you actually use:

| Surface | Where | URL field | How you sign in |
|---------|-------|-----------|-----------------|
| **Devin Cloud** | [app.devin.ai](https://app.devin.ai) sessions, including Slack / Teams | Form field **Server URL** | Browser OAuth on the first session that calls a Sketa tool |
| **Devin CLI / Devin Local** | `devin` in the terminal; default agent in new Devin Desktop tabs | `"url"` | `devin mcp login sketa` |
| **Cascade** | Legacy agent in Devin Desktop | `"serverUrl"` | Browser OAuth on the first tool call |

Using the wrong field name (`url` vs `serverUrl`) makes Devin **silently ignore** the server.

## Setup (Devin Cloud)

<Steps>
  <Step title="Open MCP servers">
    Go to **[Settings → Connections → MCP servers](https://app.devin.ai/settings/connections?tab=mcps)** and click **Add a custom MCP**.
  </Step>
  <Step title="Add the Sketa server">
    Fill in the form. You do not paste JSON — Devin uses the web form.

    | Field | Value |
    |-------|-------|
    | **Server Name** | `Sketa` |
    | **Short Description** (optional) | `Draw diagrams and slides in Sketa` |
    | **Transport** | **HTTP** |
    | **Server URL** | `https://sketa.app/mcp` |
    | **Authentication** | **OAuth** |
    | **Access** | **Personal** |

    Leave **OAuth credentials** (client ID / secret) empty. Sketa uses OAuth 2.1 with Dynamic Client Registration — Devin discovers `/.well-known` from the URL and registers itself.

    Set **Access** to **Personal** so each Devin member signs in to their own Sketa account. **Organization** shares one Sketa login across every member's sessions — only use that if you intend a shared workspace login. Personal is not a security boundary: other org members can still open your Devin sessions.

    Do not choose **None**. **Auth Header** with an `Authorization: Bearer sketa_...` [API key](/knowledge-base/developers/api-keys) also works, but OAuth is simpler.
  </Step>
  <Step title="Save, then start a session">
    Click **Save**.

    **Test listing tools** may fail until OAuth completes. That flow runs on the **first Devin session**, not at save time. Start a new Cloud session (or tag Devin in Slack / Teams) and ask it to use Sketa. Devin opens a browser window. Sign in, pick the **Workspace** this connection may use and click **Allow**. To use another workspace, connect again and pick it.
  </Step>
  <Step title="Verify the connection">
    In that session, ask:

    ```
    List my Sketa scenes
    ```

    Devin should call Sketa tools. If it answers without tools, tell it to use the **Sketa** MCP server. See the [Tools reference](/ai/tools-reference) for every tool and the recommended drawing workflow.
  </Step>
</Steps>

## Authentication

Use **OAuth**: a browser sign-in that binds the connection to one Plus workspace you pick. Leave OAuth client ID and secret empty: Sketa supports Dynamic Client Registration.

Sketa's MCP server also accepts an [API key](/knowledge-base/developers/api-keys) sent as an `Authorization: Bearer sketa_...` header, if you prefer a key to a browser sign-in. A key carries only its abilities, and a workspace key sees shared collections only.

To disconnect, remove the server from Devin. Leaving the workspace also ends the connection.

## What you can do

Once authorized, Devin can:

| Task | Examples |
|------|----------|
| **Drawing** | Draw diagrams with automatic layout; add shapes, arrows, sticky notes and images; search and edit scenes; take screenshots to check the result |
| **Slides** | Add slides, write speaker notes, reorder and hide slides |
| **Scenes and collections** | List, search, create, rename, move, pin and delete |
| **Workspace** | Read the workspace; manage members, invites and teams; read the audit log |

Members, invites, teams and the audit log need an admin. See [Permissions](/ai/introduction#permissions).

On Cloud, the same custom server is available in web sessions and in sessions started from [Slack](https://docs.devin.ai/integrations/slack) or [Microsoft Teams](https://docs.devin.ai/integrations/microsoft-teams).

## Devin CLI and Devin Local

[Devin CLI](https://docs.devin.ai/cli/extensibility/mcp/configuration) and [Devin Local](https://docs.devin.ai/desktop/devin-local) (the default agent in new Devin Desktop tabs) share this config. The URL field is `"url"`, not `"serverUrl"`.

Install the CLI if you do not have it:

```bash
curl -fsSL https://cli.devin.ai/install.sh | bash
```

Unlike Cascade, Devin Local and the CLI **prompt before every MCP tool** until you allow the server. If Sketa is connected but Devin never calls a tool, approve the prompt or add `mcp__sketa__*` to `permissions.allow`.

<Steps>
  <Step title="Add the server">
    ```bash
    devin mcp add sketa https://sketa.app/mcp
    ```

    Default scope is **local**: `.devin/mcp_config.local.json` (gitignored). Change scope with `-s`:

    | Scope | Command | File |
    |-------|---------|------|
    | Local (default) | `devin mcp add sketa <URL>` | `.devin/mcp_config.local.json` |
    | Project (shared) | `devin mcp add -s project sketa <URL>` | `.devin/mcp_config.json` |
    | User (all projects) | `devin mcp add -s user sketa <URL>` | `~/.config/devin/mcp_config.json` (Windows: `%APPDATA%\devin\mcp_config.json`) |
  </Step>
  <Step title="Sign in">
    ```bash
    devin mcp login sketa
    ```

    Complete the Sketa browser sign-in: pick the **Workspace** this connection may use and click **Allow**. First use can also open this flow. Do **not** pass `--scopes` — Sketa needs the `mcp:use` scope that Devin discovers from the server. A custom scope list will fail.

    To sign in again later:

    ```bash
    devin mcp logout sketa
    devin mcp login sketa
    ```

    To remove the server: `devin mcp remove sketa`.
  </Step>
  <Step title="Verify">
    ```bash
    devin mcp list
    devin mcp get sketa
    ```

    Then ask Devin in the CLI or a Devin Local tab:

    ```
    List my Sketa scenes
    ```
  </Step>
</Steps>

Equivalent JSON (no `Authorization` header, no `serverUrl`):

```json
{
  "mcpServers": {
    "sketa": {
      "url": "https://sketa.app/mcp",
      "transport": "http"
    }
  }
}
```

`transport` is optional — a URL defaults to Streamable HTTP. Do not set `"sse"`. Do not add `headers`, `oauthClientId`, or `oauthClientSecret`.

Before CLI v3000.3 (Local 3.6), MCP servers lived under `mcpServers` inside the main `config.json` files. Current versions use the dedicated `mcp_config.json` files above and migrate the old key on startup. Some Devin Local docs still show `.devin/config.json` — if that file has `mcpServers`, the CLI moves it on the next start.

## Devin Desktop (Cascade)

New Devin Desktop tabs use [Devin Local](#devin-cli-and-devin-local). Configuring only the Cascade file does **not** give new tabs Sketa — add the CLI config too.

The legacy **Cascade** agent still uses a separate file and `"serverUrl"`. Enterprise orgs may need an admin to turn MCP on in settings. Cascade can load at most **100 tools** across all MCP servers; if other servers fill that budget, disable unused tools on the Sketa MCP settings page.

<Steps>
  <Step title="Open the MCP config">
    In Cascade, click **MCPs** (top-right of the Cascade panel) or go to **Devin Settings → Cascade → MCP Servers**, then **View raw config**. You can also edit the file directly:

    - Desktop Cascade: `~/.codeium/windsurf/mcp_config.json`
    - JetBrains Windsurf plugin: **Settings → Tools → Windsurf Settings → Add Server**, raw file `~/.codeium/mcp_config.json`
  </Step>
  <Step title="Add Sketa">
    ```json
    {
      "mcpServers": {
        "sketa": {
          "serverUrl": "https://sketa.app/mcp"
        }
      }
    }
    ```

    No `headers` needed. After saving, refresh MCP / reload the window.
  </Step>
  <Step title="Sign in and verify">
    Trigger a Sketa tool call. Cascade opens a browser window. Pick the **Workspace** this connection may use and click **Allow**, then ask:

    ```
    List my Sketa collections
    ```
  </Step>
</Steps>

<Tip>
  Cascade uses `"serverUrl"`. Devin Local / CLI use `"url"`. The [official Devin docs](https://docs.devin.ai/work-with-devin/devin-mcp) say the wrong field name is ignored with no error.
</Tip>

## Troubleshooting

<AccordionGroup>
  <Accordion title="I added mcp.devin.ai or a cog_ key">
    That is [Devin's own MCP server](https://docs.devin.ai/work-with-devin/devin-mcp) (Devin as a tool for other clients). Remove it. Sketa's URL is `https://sketa.app/mcp` with OAuth — no Devin API key.
  </Accordion>
  <Accordion title="Add a custom MCP is missing">
    You need **Manage MCP Servers**. Ask an org admin, or use **Suggest MCP Integration**. The same permission is required to finish OAuth on Cloud.
  </Accordion>
  <Accordion title="Test listing tools fails right after Save">
    Expected for OAuth. Devin authenticates on the first session, not at save time. Start a Cloud session, complete the browser sign-in and click **Allow**, then try again.
  </Accordion>
  <Accordion title="The server is added but Devin does not call Sketa tools">
    Finish OAuth in the surface you are using (Cloud session, `devin mcp login`, or Cascade). Tokens are not shared across surfaces. Start a **new** session and say you want the **Sketa** MCP server.

    On Devin Local / CLI, also approve the MCP permission prompt (or allow `mcp__sketa__*`). Cascade does not prompt the same way. Check the session logs for MCP errors.
  </Accordion>
  <Accordion title="Auth required, AuthRequired, or Needs auth">
    Official Devin CLI/Local wording when OAuth is missing or expired. Run `devin mcp login sketa`, or click **Authenticate** on the Devin Local MCP card. Cloud: start a new session and complete the sign-in.
  </Accordion>
  <Accordion title="I passed --scopes on devin mcp login">
    Remove the flag and log in again. `--scopes read,write` (or any custom list) skips Sketa's `mcp:use` scope and the tools never authorize.
  </Accordion>
  <Accordion title="Config looks correct but the server never appears (Desktop / CLI)">
    You used the wrong URL key. Cascade needs `"serverUrl"`. CLI and Devin Local need `"url"`. The wrong key is ignored with no error. Also check you edited the file for that agent — Cascade does not read `.devin/mcp_config.json`.
  </Accordion>
  <Accordion title="devin mcp add did not update the file I edited">
    Default scope is **local** (`.devin/mcp_config.local.json`), not `~/.config/devin/mcp_config.json`. Use `-s user` or `-s project`, or edit the local file.
  </Accordion>
  <Accordion title="HTTP 402 — Sketa Plus required">
    The connection works, but the workspace it is bound to does not have Sketa Plus. Subscribe in **Settings → Billing**, or reconnect and pick a Plus workspace. See [Introduction](/ai/introduction#troubleshooting).
  </Accordion>
  <Accordion title="HTTP 401 or I need to sign in again">
    The OAuth session expired or was revoked. Cloud: start a new session and approve again. CLI: `devin mcp logout sketa` then `devin mcp login sketa`. Cascade: trigger a tool call and complete the browser flow.
  </Accordion>
  <Accordion title="A tool says “Not found.”">
    The resource is outside the workspace the connection is bound to, or you cannot see it (another member's private collection; a team-restricted collection for a workspace key). Ask the assistant to list scenes or collections first instead of guessing ids.
  </Accordion>
  <Accordion title="Browser does not open during CLI sign-in">
    Over SSH or inside a container, `devin mcp login` prints the authorize URL instead of opening a browser. Copy it into a local browser, pick the workspace, click **Allow**, and the CLI picks up the callback. If the loopback port is blocked, finish OAuth on a machine that can receive the callback, or connect with an [API key](/knowledge-base/developers/api-keys) header instead.
  </Accordion>
  <Accordion title="Enterprise team blocked the server">
    A Devin admin can disable MCP, require it to be turned on in team settings, or allowlist only certain servers. Cascade on Enterprise is off until an admin enables it. If Sketa never connects on a Teams / Enterprise plan, ask an admin to allow a custom HTTP server at `https://sketa.app/mcp`.
  </Accordion>
</AccordionGroup>
